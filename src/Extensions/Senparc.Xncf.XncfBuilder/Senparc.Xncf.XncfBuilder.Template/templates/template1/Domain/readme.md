# Domain folder

The `Domain` folder contains core business logic and domain models. These models express essential business concepts and rules and form the foundation of the module.

Common building blocks in `Domain` include:

- **Entity**: business objects with identity whose state changes over time.
- **Value object**: objects without identity that describe attributes; values are immutable.
- **Aggregate**: a cluster of entities and value objects persisted and versioned as one unit.
- **Aggregate root**: the aggregate entry point responsible for invariants and consistency.
- **Domain service**: operations that do not naturally belong to a single entity or value object.
- **Domain event**: significant business occurrences used for decoupling and audit trails.

Keep core rules and models in `Domain` so the module stays clear and maintainable.

## Folder layout

By default, `Domain` contains three subfolders: `Migrations`, `Models`, and `Services`.

### Migrations

Database migration artifacts for the domain model. They keep the database schema aligned with the model.

Migrations are usually generated by the XncfBuilder module; avoid hand-editing unless you know the impact.

### Models

Entities, value objects, aggregates, and aggregate roots.

### Services

Domain services and domain events that coordinate multiple domain types.

Place each kind of artifact in its subfolder to keep the layout consistent across XNCF modules.
